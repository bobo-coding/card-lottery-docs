# 单位经济模型

> 前置：[03 §0 核心矛盾](./03-breaking-mechanics-japan.md) · [04 平台产品设计](./04-platform-product-design.md)
> **本文目的**：03 §0 断言"Breaking 毛利远低于 Oripa"并将其列为最大未验证假设，但从未量化。
> 本文把它算出来。
>
> ⚠️ **全部数值为示例假设，非真实数据**。用途是揭示**结构与敏感度**，不是预测收益。
> 真实数字须按 §9 清单逐项填入后重算。
>
> **本文分两层，价值不同**：
> - **结构层**（§1–§3、§7–§8）：透明性悖论、成本曲线差异、合单系数是主杠杆
>   —— **不依赖数字，从设计约束推出**，见 [00 §6](./00-framework.md)
> - **测算层**（§5–§6）：具体数值为示例，用于展示敏感度
>   —— **数字可换，但"k 是决定性变量"这一结构不变**

## 0. 三个结论

1. **透明性悖论**：Breaking 的信任优势与毛利天花板**是同一个属性** —— 密封盒零售价公开，
   用户能直接算出溢价；Oripa 的不透明正是其定价权来源。
2. **成本曲线本质不同**：Oripa 随服务器扩张，**Breaking 随人力扩张**。
   L1 + L3 两条法律约束强制 **100% 实物履约**，而 Oripa 大部分交易根本不发货。
3. **合单发货决定生死**：按示例假设，单场逐位发货需 **+41% 溢价**才保本，
   合单后降至 **+7.5%** —— **这直接推翻 [04 §8.1](./04-platform-product-design.md) 的"MVP 用商家直发"建议。**

## 1. 结构对比：钱从哪来，成本在哪

### 1.1 Oripa（DOPA / 日本トレカセンター）

| 项 | 机制 |
|---|---|
| 收入 | 池销售额 |
| 成本 | 卡的**買取相場**（进价），显著低于**販売相場**（标价） |
| 利润源 1 | **进销价差**：按販売相場组池，按買取相場进货 |
| 利润源 2 | **积分变换**：未中卡以高于買取价的积分回收，抬高名义还原率且钱不出站 |
| 利润源 3 | **估值权**：卡值多少由平台自己定 |
| 利润源 4 | **积分沉淀**：多数用户换积分继续抽，**卡从未出库** |
| **履约率** | **低** —— 大量交易不发货 |
| **扩张方式** | **软件扩张**，边际成本趋近于零 |

### 1.2 Breaking（本平台）

| 项 | 机制 |
|---|---|
| 收入 | 位售价总额 × 平台佣金 |
| 成本 | 盒进价 + **每位分拣打包运费** + 录像采集 + 仲裁客服 |
| 利润源 | **仅佣金**（利润源 2/3/4 被 L1 排除，估值权因卡为实物且市价公开而不存在） |
| **履约率** | **100%** —— L3 要求每位保底实物，**每一位都必须发货** |
| **扩张方式** | **人力扩张**，边际成本不降 |

> **L1（不设现金回收）+ L3（每位保底实物）不只是砍掉利润，
> 它们把履约率从 Oripa 的"少数"锁死为"全部"。**
> 这是 03 §0 未识别的部分 —— 核心矛盾比原先描述的更重。

## 2. 透明性悖论

**Breaking 的定价权被它自己的透明性压制：**

```
Oripa：用户不知道池子成本 → 无价格锚 → 定价权在平台
Breaking：密封盒零售价公开可查 → 用户能算出溢价 → 定价权受限
```

用户随时能对比"这盒在駿河屋卖 ¥X，而这些位加起来卖 ¥Y"。
**Y/X 的比值就是溢价，是公开的、可被讨论和攻击的。**

> **信任优势与毛利天花板是同一个属性，不可分割。**
> 这是对 03 §0"两者互相咬死"更准确的表述 ——
> 不是两个独立性质在打架，而是**同一个性质的两面**。

## 3. 用户的替代方案（决定溢价上限）

用户面对三个选项，Breaking 必须在其中有位置：

| 选项 | 成本 | 得到 | 缺点 |
|---|---|---|---|
| **买整盒** | 盒市价 R | 全部内容 | 客单高；**大量不想要的卡** |
| **买单卡** | 单卡市价 P | 精确所需 | 无惊喜；**无上涨空间** |
| **买角色枠位** | S/N | 目标范围的随机 | 有溢价 |

**角色枠为什么能支撑溢价**（不只是情绪，是真实效率）：

> 一个只想要皮卡丘系卡的收藏者，买整盒要为一堆不需要的卡付钱。
> **买皮卡丘枠对他是更高效的配置** —— 这是理性的经济理由，不是赌性。
>
> 这给了 03 §3.1「角色枠是唯一球队等价物」一个额外支撑：
> 它同时具备**情感黏性**与**配置效率**，是溢价的双重来源。

**溢价上限的约束**：一旦 S/N 接近该枠内容的市价合计，理性用户会转去买单卡。
所以**溢价空间来自"目标范围内的随机性"值多少钱**，这是有限的。

## 4. 模型

### 4.1 变量

| 符号 | 含义 |
|---|---|
| `R` | 盒**市价**（公开锚点） |
| `B` | 商家**进价** |
| `N` | 位数 |
| `S` | 位售价**总额** |
| `m` | 溢价率 = `S/R − 1` |
| `c` | 平台佣金率 |
| `p` | 支付手续费率 |
| `f` | **每次发货**成本（打包 + 运费） |
| `k` | **合单系数** = 平均每次发货合并的位数 |

### 4.2 公式

```
平台收入       = S × c
商家履约成本   = (N / k) × f          ← k 是关键变量
商家毛利       = S × (1 − c − p) − B − (N / k) × f
商家保本条件   = S × (1 − c − p) = B + (N / k) × f
```

> **`N / k` 是发货次数**。k=1 表示逐位单独发货，k=4 表示平均 4 位合并一次发货。
> **合单能力直接除掉履约成本。**

## 5. 情景测算（示例假设）

⚠️ 以下数字**全为示例**，仅用于展示结构，勿作依据。

**共同假设**：`R = ¥10,000`（热门弹一盒）、`B = ¥8,500`、`N = 10`（角色枠）、
`c = 8%`、`p = 3.6%`、`f = ¥400`（一次发货）

> `c`、`p` 两个费率假设有市场锚点：Whatnot 披露定价即佣金 8% + 支付 2.9%+$0.30，
> eBay take rate 约 14%（[02 §8](./02-market-landscape.md)）。
> 即本文的佣金假设处于行业实际区间，不是随手取的数 —— 但其余变量（`B`、`f`、`k`、`m`）仍是示例。

### 情景 A：逐位发货（k = 1）—— 04 §8.1 的"商家直发"

```
履约成本 = 10 / 1 × ¥400 = ¥4,000
保本 S   = (8,500 + 4,000) / (1 − 0.08 − 0.036) = ¥14,140
溢价 m   = 14,140 / 10,000 − 1 = +41.4%
```

**若按 +20% 溢价（S = ¥12,000）定价**：

```
商家毛利 = 12,000 × 0.884 − 8,500 − 4,000 = −¥1,892   ← 亏损
```

> **逐位发货下，+20% 溢价的商家是亏钱的。** 履约成本占 S 的 33%，吞掉全部空间。

### 情景 B：合单发货（k = 4）

```
履约成本 = 10 / 4 × ¥400 = ¥1,000
保本 S   = (8,500 + 1,000) / 0.884 = ¥10,747
溢价 m   = +7.5%
```

**若按 +20% 溢价（S = ¥12,000）定价**：

```
商家毛利 = 12,000 × 0.884 − 8,500 − 1,000 = ¥1,108   （毛利率 9.2%）
平台收入 = 12,000 × 8% = ¥960
```

### 情景对比

| | k=1 逐位发货 | k=4 合单 |
|---|---|---|
| 保本溢价 | **+41.4%** | **+7.5%** |
| +20% 溢价下商家毛利 | **−¥1,892** ❌ | +¥1,108 ✅ |

> **结论：合单发货不是优化项，是模式成立的前提。**
> 而**商家直发在结构上无法合单** —— 不同商家、不同场次各自发货，k 恒等于 1。

## 6. 对 04 §8.1 的修正

[04 §8.1](./04-platform-product-design.md) 建议 "MVP 用商家直发 + 托管结算，规模化后再上集中仓"。
**按 §5 测算，这个建议在经济上不成立。**

| 方案 | k | 可行性 |
|---|---|---|
| 商家直发 | 1 | ❌ 需 +41% 溢价，超出用户接受度 |
| 商家持货合单 | 2–3 | ⚠️ 仅同商家可合，且商家须有仓储能力 |
| **平台集中仓** | **4+** | ✅ 跨商家跨场次合单 |

**修正建议**：MVP 即采用**平台集中仓**。这同时与 [04 §10](./04-platform-product-design.md) 关于
I5（录像须平台采集）的结论一致 —— 那里也推荐 **MVP 用集中开盒场地**。

> **两条独立推理指向同一个结论：集中化不是规模化后的选项，是 MVP 的前提。**
> 一条来自信任（I5 无法在商家自有场地强制），一条来自经济（k=1 时模式亏损）。

## 7. 吞吐量约束（Breaking 特有）

**Oripa 加服务器就能扩张，Breaking 不行 —— 每一场都要人拆、人分、人发。**

按情景 B（每场平台收入 ¥960）估算平台保本规模：

| 平台年固定成本（示例） | 需要场次/年 | 场次/日 | 仅开盒+归属的人力* |
|---|---|---|---|
| ¥50,000,000 | 约 52,000 | 约 143 | 约 9 FTE |
| ¥100,000,000 | 约 104,000 | 约 285 | 约 18 FTE |

\* 按每场端到端 30 分钟人力、每人每日 8 小时估算。

**结论**：
- 这是**运营密集型生意**，不是软件生意
- 人力成本随 GMV 近似线性增长，**规模效应远弱于 Oripa**
- 场地、开盒工位、分拣产能都是硬约束

## 8. 成本杠杆（按影响力排序）

| # | 杠杆 | 影响 | 实现 |
|---|---|---|---|
| **1** | **提高合单系数 k** | **决定模式是否成立**（§5） | 平台集中仓 + 鼓励累积后发货 |
| **2** | **归属自动化** | 直接压缩每场人力，决定吞吐上限 | **上架时强制提交分位清单**，开盒后自动匹配 |
| **3** | 提高每场标的价值 | 摊薄固定人力成本 | 高价弹、Case 场次 |
| 4 | 降低进价 B | 直接进毛利 | 货源议价、批量采购 |
| 5 | 开盒工位并行化 | 提升吞吐上限 | 标准化工位与流程 |

> **杠杆 2 呼应 [04 §4.2](./04-platform-product-design.md)**：
> 那里指出 ENUMERATED（角色枠）的归属判定成本最高，解法是把人工判定前移到上架。
> **本文给这个设计加上了经济权重 —— 它不是运营便利，是吞吐量的决定因素，
> 而吞吐量决定这门生意的规模上限。**

## 9. 待填真实数据

**本文所有结论的可靠性取决于以下数字，全部需要实测：**

| # | 变量 | 获取方式 | 影响 |
|---|---|---|---|
| 1 | `R` 各弹盒市价 | 駿河屋等零售监测 | 溢价锚点 |
| 2 | `B` 商家实际进价 | 供应商询价 | 毛利基础 |
| 3 | `f` 单次发货成本 | 日本物流报价（ゆうパケット等） | **履约成本** |
| 4 | **`k` 实际合单系数** | **须用户行为验证** | **模式生死** |
| 5 | `m` 用户可接受溢价 | **A/B 测试** | **模式生死** |
| 6 | 每场端到端人力工时 | 实操计时 | 吞吐与人力预算 |
| 7 | 平台年固定成本 | 团队与场地规划 | 保本规模 |

> **4 和 5 是仅有的两个"生死变量"**，且都无法从公开数据获得，**只能实测**。
> 这就是 [03 §8.2](./03-breaking-mechanics-japan.md) 说的 MVP 第一验证目标 ——
> 本文把它从一个模糊问题细化成了两个可测量的数字。

## 10. 验证设计

**在投入集中仓、开盒场地等重资产前，用最小成本测这两个数：**

| 测什么 | 怎么测 | 通过标准（示例） |
|---|---|---|
| **`m` 溢价接受度** | 同一批标的，按 +10% / +20% / +30% 三档定价开场，看售罄率与售罄速度 | 至少一档能稳定 100% 售罄（L2 要求全售罄） |
| **`k` 合单系数** | 提供"暂存合单"选项，观察用户实际累积几位才发货 | k ≥ 3 |

> **若 `m` 上限低于保本溢价，或 `k` 稳定低于 3，则模式的经济基础不成立**，
> 应在此处停止，而不是继续投入。这是本文最重要的用途。
