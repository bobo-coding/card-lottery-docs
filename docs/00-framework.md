> **本文的位置**：01–05 是**结论**，本文是**推导**。

>

## 1. 第一性分解

一次开箱交易 = 用户支付 → 经过某个随机过程 → 获得标的。
拆成四个环节，**每个环节都可以问同一个问题：谁控制它？**

| 环节 | 内容 | 控制者可能是 |
|---|---|---|
| **E1 标的构成** | 池子/盒子里有什么 | 厂商 / 平台 / 商家 |
| **E2 随机产生** | 随机数从哪来 | 平台 / 厂商（物理密封） |
| **E3 归属分配** | 结果如何映射到买家 | 平台 / 商家 |
| **E4 交付履约** | 实物如何到达买家 | 平台 / 商家 |

> **所有信任问题都源于同一件事：某个环节的控制者能否不被察觉地操纵它。**
> 这是全套文档的单一出发点。

## 2. 信任的结构理论

### 2.1 控制点分析法

对每个环节，问三个问题：

```
Q1  谁控制这个环节？
Q2  控制者能否不被察觉地操纵它？
Q3  操纵的收益有多大？
```

**风险 = Q2 为「能」且 Q3 为「大」的环节。** 信任架构就是针对这些环节的对策集合。

### 2.2 三种信任机制及其适用边界

| 机制 | 原理 | 适用环节 | 失效场景 |
|---|---|---|---|
| **密码学承诺** | 先承诺后揭示，事后可验算 | **可计算的随机**（E2、E3） | 物理过程无法承诺 |
| **物理证据** | 影像、封条、来源凭证 | **物理过程**（E1、E2 的开封、E4） | 证据本身可被伪造/剪辑 |
| **控制权分离** | 让操纵需要多方串谋 | **无法自证的环节** | 各方可串谋时失效 |

> **关键**：三者不可互相替代。
> 密码学证明不了"这盒没被调包"，影像证明不了"这个随机数没被试算过"。
> **必须按环节分别配置。**

### 2.3 核心命题

> **信任来自控制权的分散，而不是控制者的承诺。**

推论：

- **一个环节由单方完全控制 → 只能靠该方自证 → 信任上限受限于该方声誉**
- **一个环节需多方配合才能操纵 → 结构性可信 → 不依赖任何一方的诚信**

这条命题生成了全套文档的所有核心结论。以下逐一展示。

### 2.4 用该理论推导三种形态

**Oripa（DOPA 等）**

| 环节 | 控制者 | 可操纵性 | 对策 |
|---|---|---|---|
| E1 标的构成 | **平台**（自己组池） | 高 | 只能靠自愿公示 |
| E2 随机产生 | **平台**（服务端 RNG） | 高 | 密码学承诺 |
| E3 归属 | 平台 | 高 | 同上 |

> **E1 与 E2 同属一方 → 无控制权分散 → 信任上限 = 平台声誉。**
> 这就是 Oripa 结构性的信任缺陷：无论公示多少，池子终究是它组的。
> ⇒ 生成 [03 §4.3](./03-breaking-mechanics-japan.md) 的差异化论点。

**Breaking（单运营方）**

| 环节 | 控制者 | 可操纵性 | 对策 |
|---|---|---|---|
| E1 标的构成 | **厂商**（密封） | **平台不可控** | 天然可信 |
| E2 开封随机 | 厂商 | 平台不可控 | 影像证明未调包 |
| E3 分位随机 | **平台** | 高 | **密码学承诺** |

> **E1 与 E3 分属不同方 → 结构性优于 Oripa。**
> ⇒ 生成 [01 §2.C](./01-product-taxonomy.md) 的"两段随机"划分：
> 两段随机的控制者不同，**对策必须不同**，混作一谈必然出错。

**Breaking（多商家平台）**

引入商家后，若商家同时控制 E3 与 E4，则**商家取代平台成为新的单点**
——这正是北美三起信任事故的结构成因。

| 环节 | 控制者 | 设计 |
|---|---|---|
| E1 | 厂商 | 密封，无人可改 |
| E2 开封 | 厂商 | 平台采集影像 |
| E3 分位 | **平台**（商家无权） | 密码学承诺 |
| E4 履约 | 平台或商家 | 托管 + 记录 |

> **三方分权**：厂商定内容、平台定分位与影像、商家两者皆无权。
> **任何单方都无法独自操纵，串谋必然留痕。**
> ⇒ 生成 [04 §0.1](./04-platform-product-design.md)。

### 2.5 由理论直接推出的设计规则

| 规则 | 来自 |
|---|---|
| 随机必须**由平台执行**，商家无权触发或重跑 | E3 控制权归属 |
| 影像必须**由平台采集**，商家不得上传替换 | 物理证据机制的失效场景 |
| 种子承诺必须**先于售位** | 密码学承诺的有效前提 |
| 分位结果必须**先于开盒公示** | 使 E3 与 E1 在时间上不可耦合 |
| 商家关联账号**不得购买自家场次** | 防止商家同时是买卖双方 |

## 3. 约束的推导链

**从外部风险到系统不变量，每一步都可追溯：**

```
① 法律风险源（外部给定）
   ├─ 现金还流构成"争夺现金"           → 赌博风险最高的配置
   ├─ 只卖部分位、剩余自留              → 平台成为对赌方
   └─ 结构上注定有人一无所获            → "有人得利有人损失"

② 法律硬约束 L1–L4（03 §6.2）
   L1 不设现金回收        ← ①现金还流
   L2 100% 售罄才开拆     ← ①部分贩卖
   L3 每位保底实物        ← ①部分参加者纯亏
   L4 随机可验证+全程录像  ← §2 信任理论

③ 系统不变量 I1–I9（04 §3）
   L1 → I3   不提供现金回收/可提现余额
   L2 → I2   成团阈值=100%，不得自持位
   L3 → I1   每位最低张数>0 且分位穷尽
   L4 → I4   随机由平台执行
   L4 → I5   录像由平台采集
   L4 → I6   种子承诺先于售位
   ①  → I7   禁 Repack（重封包使 E1 回到平台控制）
   ①  → I8   商家关联账号不得购位
   ①  → I9   禁按稀有度分位（造出确定性亏损位）
```

### 3.0 第二层约束：资本市场可接受性

上述链条只覆盖**法律层**。[06](./06-china-hobby-stocks.md) 的卡游案例揭示了**第二层**：

```
法律层：是否违法          → 违法则处罚、停业
资本层：是否可被定性为     → 被定性则上不了市、融不到钱
        "收割未成年人"
        "变相赌博"
```

> **合法 ≠ 可资本化。** 卡游年营收 ¥100 亿、毛利 67%、市占 71%，未被认定违法，
> 但监管问询与舆论将其模式定性为"灰色地带"，两次递表失效、对赌触发回购。
>
> **资本层门槛高于法律层。** 因此 L1–L4 的意义需重估：
> 它们不只是规避处罚，更是**保留融资与退出通道**；
> 而 §2 的信任架构也不只是产品竞争力，**它是这门生意能否被资本接受的前提**。

### 3.1 为什么必须是"不变量"而非"规范"

单运营方时，L1–L4 可以是运营策略；
**多商家时不行** —— 平台无法逐场审核商家意图。

> **约束层必须在配置层之上：商家配置不出违规场次，而不是配置了再被驳回。**
> 这是 [04 §3](./04-platform-product-design.md) 的架构决策，其必要性完全来自"多商家"这一结构变化。

## 4. 形态选择的推导

不是偏好，是三步排除：

```
第一步：选 E1 的控制者
  平台控制 E1（Oripa/Kuji）  → 信任上限受限（§2.4）
  厂商控制 E1（Breaking）    → 结构性可信
  ⇒ 选 Breaking

第二步：Breaking 需要"分区单元"来定义 E3
  美国用球队 —— 需满足三属性：可穷尽、有情感、事前公开
  日本 TCG 无球队 ⇒ 依赖球队的玩法全部失效
  ⇒ 必须重建分区单元

第三步：在日本 TCG 中寻找满足三属性的分区
  包号：可穷尽 ✅ 事前公开 ✅ 有情感 ❌
  稀有度：造出确定性亏损位，违反 L3/I9 ❌
  角色：三属性全部满足 ✅
  ⇒ 角色枠（[03 §3](./03-breaking-mechanics-japan.md)）
```

> **"分区单元三属性"是可复用的判据**：进入任何新品类（体育卡、其他 TCG）时，
> 用它筛选分区单元即可，不必重新推导。

## 5. 决策依赖图

**根决策变了，下游全部要重推；叶决策可以独立调整。**

```
【根】E1 控制者归谁 ──▶ 决定信任架构、法律结构、经济结构
  │
  ├─【干】是否多商家 ──▶ 决定约束是"规范"还是"不变量"
  │                  ──▶ 决定是否需要三方分权与商家治理
  │
  ├─【干】是否回收闭环 ──▶ 决定是单向售卖还是双向回路
  │                    ──▶ 决定履约率（少数 vs 100%）
  │                    ──▶ 决定成本曲线（软件扩张 vs 人力扩张）
  │
  ├─【枝】分区单元选择 ──▶ 决定归属判定成本与吞吐量
  │
  └─【叶】直播/录像、定价、玩法组合、UI ──▶ 可独立调整
```

> **两个"干"级决策已定且互相强化**：不做回收（L1）既是法律安全侧，
> 又使 E1 保持在厂商手中（不回收就不需要估值权）。
> 但代价是履约率 100% 与人力扩张的成本曲线 —— 见 §6。

## 6. 结构性代价（不可通过优化消除）

设计选择必然带来的后果，**只能承受或改变根决策，不能靠执行力绕过**：

| 选择 | 收益 | 结构性代价 |
|---|---|---|
| E1 交给厂商 | 信任结构性优势 | **失去估值权与组池权** → 无 Oripa 式利润 |
| 不做回收（L1） | 法律安全侧 | **履约率 100%** → 人力线性扩张 |
| 每位保底实物（L3） | 降低赌博性 | 同上，且每位都要分拣打包 |
| 影像可验证（L4） | 信任底座 | 采集、存储、集中场地成本 |
| 标的是密封盒 | 内容不可操纵 | **零售价公开 → 溢价可被用户计算** |
| 标的是厂商已发行品 | **无需 IP 授权** → 无授权临期与分成风险 | **无 IP 护城河** → 谁都能采购同样的盒 |

> **最后一行是最深的一条**：标的公开可查是信任的来源，
> 同时也让定价权受限 —— **信任优势与毛利天花板是同一个属性的两面**，不可分割。
> ⇒ [05 §2](./05-unit-economics.md) 的透明性悖论。

## 7. 系统组件（由体系推出）

**每个组件都对应上文的一个环节或约束，没有多余模块：**

| 组件 | 职责 | 来自 |
|---|---|---|
| **约束校验器** | 拒绝违反 I1–I9 的配置 | §3.1 |
| **分位方案引擎** | 可插拔的分区定义与归属规则 | §4 E3 |
| **可验证随机** | 承诺-揭示、熵源、复算 | §2.2 密码学机制 |
| **影像采集与归档** | 平台侧采集、防替换、永久可查 | §2.2 物理证据机制 |
| **场次状态机** | 保证关键时序不可调换 | §2.5 时序规则 |
| **开盒记录** | 跨环节的证据链，可独立复算 | §2.1 全部环节 |
| **商家治理** | 资质、权限边界、保证金、分级 | §2.4 多商家结构 |
| **托管结算** | 资金与履约解耦 | E4 |
| **归属与履约** | 判定、集中仓、合单 | E4 + §6 代价 |

> **反向检查**：任何提议的新模块，若无法对应到某个环节或约束，
> 应质疑其必要性。这是控制范围蔓延的判据。

## 8. 全局不变量速查

**任何设计变更都不得违反：**

| # | 不变量 | 违反后果 |
|---|---|---|
| 1 | 商家不得控制 E2/E3（随机与影像） | 三方分权失效，退化为 Whatnot |
| 2 | 种子承诺先于售位，分位公示先于开盒 | 密码学承诺失去意义 |
| 3 | 每位保底实物，分位方案穷尽且互斥 | 触及"部分参加者纯亏" |
| 4 | 成团 100%，无人自持位 | 平台/商家成为对赌方 |
| 5 | 无现金回收、无可提现余额 | 构成现金还流 |
| 6 | 开盒记录不可变、可独立复算 | 失去核心资产 |

## 10. 数据在本体系中的地位

**明确边界，避免把证据误当论证：**

| 结论类型 | 依赖数据？ | 例 |
|---|---|---|
| **结构性结论** | ❌ 不依赖 | 三方分权、两段随机、约束推导链、透明性悖论 |
| **优先级判断** | ⚠️ 方向性依赖 | 主攻 TCG 而非体育卡、直播不作为收入前提 |
| **量化门槛** | ✅ 强依赖 | 保本溢价率、合单系数阈值、吞吐量估算 |

> **第一类不会因数据错误而失效** —— 它们从结构推出，不从数字推出。
> 第二类即使量级有偏，方向通常仍成立。
> **只有第三类必须以实测数据重算**，且已在 [05 §9](./05-unit-economics.md) 列为待填清单。
>
> 阅读本套文档时，**若对某个数字存疑，先确认它支撑的是哪一类结论。**
