## 0. 三条结论

1. **借形不借魂**：DOPA 的界面语言（场次卡片、残口进度、最低保证、フルスクリーン演出、获得商品一览）
   可以直接借用；但其**价值机制**（充值点数、ポイント変換、月度重置的消费等级、演出即随机）
   与 L1/I3 或资本层约束冲突，**必须拒绝或改造**。判据见 §1.3。
2. **演出只能呈现已确定的真实结果**：DOPA 的演出本身就是随机发生的地方；
   本平台的随机发生在**分位公示（平台、可验证）**与**开封（厂商、物理）**两处，
   演出只能作为这两个事件的**呈现层**，不得制造、暗示或模拟任何随机。
3. **Hobby 板块给产品的约束比给机会多**：会员与复购是收入主体（泡泡玛特），
   但"诱导消费 / 未成年人"是资本否决点（卡游）。因此成长体系**不得以消费额驱动的周期重置为核心**，
   年龄门槛从 MVP 起就是 P0。

### 1.3 处置判据：采纳 / 改造 / 拒绝

对每个 DOPA 模式问两个问题：

```
Q1  它依赖的机制，与 L1–L4 / I1–I9 冲突吗？        冲突 → 拒绝
Q2  它会被资本层定性为"诱导消费/变相赌博"吗？     会 → 改造或拒绝
两问都否 → 采纳
```

| DOPA 模式 | 处置 | 理由 |
|---|---|---|
| D1 品类 Tab / D2 排序 / D3 场次卡片 | ✅ **采纳** | 纯界面语言，用户已习惯；卡片字段改造见 §4.1 |
| D4 Banner | ✅ 采纳，**禁止折扣类首购钩子作为主 Banner** | 90%OFF 首购属获客补贴，可做但不作为品牌第一印象（H4） |
| D5 全屏演出 | 🔧 **改造** | 只能包装真实事件（分位公示、开封高光），见 §4.3 |
| D6 充值点数 | ❌ **拒绝** | 预付点数 ⚠️ 可能落入資金決済法「前払式支払手段」；且点数把价格抽象化，削弱"盒价公开、溢价可算"的透明叙事（05 §2）。**按位直接支付** |
| D7 获得商品 → 发送或ポイント変換 | 🔧 **改造**：保留「获得商品一覧」界面，**删掉ポイント変換**；3 日发送期限改为**寄存（集中仓）+ 合单发货** | ポイント変換 = 回收闭环，直接违反 L1/I3；寄存反而提升 `k`（05 §6） |
| D8 不可逆、不退款 | ❌ 拒绝 | 本平台流拍/中止/录像中断**必须全额退款**（04 §5.2） |
| D9 消费等级 + 月度重置 | 🔧 **改造** | 保留等级的"身份感"，去掉消费额周期重置与购点加赠，见 §3 M8 |
| D10 登录奖励 / 推送 / 邀请 | 🔧 改造 | 推送以**履约节点**为主（分位公示、开盒开始、发货），而非"新抽池上线"催促 |
| D11 18+ | ✅ 采纳并**加强** | 不止商店评级，购位前实名 + 年龄验证（H3） |
| D12 排出顺序公开 | ✅ 采纳并**超越** | DOPA 公开的是运营自报的结果；本平台公开的是**可复算输入 + 录像锚点** |

> **最痛的一条是 D6/D7**：充值点数 + ポイント変換 是 DOPA 高频循环（抽 → 换点 → 再抽）的引擎，
> 也是 03 §4.4 承认的"黏性极强"的来源。拒绝它们意味着本平台**天然更低频**。
> 这不是界面能补回来的，是 L1 的结构代价（00 §6）。§3 M8 的会员设计只能缓解，不能消除。

## 2. 信息架构

```
底部 Tab（App）/ 顶部导航（Web）
├─ ホーム        场次发现：品类 Tab、排序、场次卡片流、即将开盒
├─ LIVE         直播中 / 即将开始 / 回放（直播是增益 → 非首 Tab）
├─ マイ枠        我的位：售位中 / 待开盒 / 已归属，分位公示结果
├─ コレクション   获得商品一覧：寄存中 / 发货中 / 已签收
└─ マイページ     会员、验证记录、支付、实名与年龄、设置、帮助
```

**与 DOPA 的结构差异**：DOPA 的核心循环是 ホーム → 抽 → 演出 → 商品一覧（单页闭环，分钟级）；
本平台的核心循环跨越**售位 → 满员 → 分位公示 → 开盒 → 归属 → 寄存/发货**，是**天级**的。
因此多了「マイ枠」这个**等待态**的一级入口 —— 它是 DOPA 没有、本平台必须做好的页面。

#### M8 会员与成长

**设计约束**（来自 §1.3 D9 改造 + H1/H4）：

```
✅ 保留：等级的身份感与可见性（H1 会员即收入主体）
❌ 去掉：消费额驱动的月度重置（"不花就掉级"是典型消费压力机制）
❌ 去掉：购点加赠（本平台无点数）
✅ 替换：权益为非现金、非折扣为主 —— 优先购位窗口、寄存免费期延长、开盒提醒优先级
```

## 4. 关键界面预案

### 4.1 场次卡片（沿用 D3 布局，替换字段语义）

```
┌──────────────────────────────┐
│ [BOX 实拍 · 封条可见]           │
│ ポケカ「XXX」2BOX キャラ枠      │
│ ─────────────────────────── │
│ ¥2,800〜/枠   参考: BOX ¥5,400 │  ← D3 的单价；新增参考零售价（透明）
│ 保底: 各枠 3 パック以上          │  ← 替代 D3「最低保証 ¥xxx」
│ ███████████░░░ 残り 4/20 枠    │  ← D3 残口，语义变为"满员进度"
│ 開封 9/28 20:00  ・ 検証可能 ✓  │  ← 新增：承诺时刻 + 种子已承诺标
│ [キャラ枠] [自営] [残りわずか]   │  ← D3 标签体系
└──────────────────────────────┘
```

**字段语义替换**：

| DOPA 字段 | 本平台字段 | 语义变化 |
|---|---|---|
| 最低保証（¥ 估值） | **保底（实物张数/包数）** | 从运营自定估值 → 厂商实物，不需要估值权 |
| 残り〇/〇口 | 残り〇/〇枠 | 从"库存"→"距满员开封" |
| — | **参考零售价** | 透明性悖论的正面使用：让用户算得出溢价 |
| — | **検証可能 ✓** | 种子已承诺；点开直达 hash |

> ⚠️ **参考零售价会让用户直接算出溢价** —— 这正是 05 §2 透明性悖论。
> 显示它是信任策略的一部分，但也是定价上限的一部分。是否默认显示，
> **应作为 `m` 实测的 A/B 变量之一**，而不是先验决定。

### 4.2 场次详情首屏顺序

```
① 标的实拍 + 封条照片
② 保底承诺 + 分位方案（每位定义与价格）
③ 满员进度 + 截止时刻 + "未满员全额退款"
④ 开封时刻 + 种子承诺 hash（可复制）
⑤ 商家/自营标识
⑥ [購入] 按钮
```

> 顺序依据：日本用户"要证明不要氛围"（03 §2.2）→ 证据在按钮之前，而不是在页面底部。

### 4.3 演出规则（D5 改造）

DOPA 的演出是**随机发生的时刻**；本平台只能在**两个真实事件**上做演出：

| 事件 | 真实随机来源 | 可做的演出 | 禁止 |
|---|---|---|---|
| **分位公示** | 平台可验证随机（已计算完成） | 位号翻牌 / 角色枠揭示动画；演出结束即显示验证入口 | 演出中"差一点"类近失效果（结果已定，暗示可能性即误导） |
| **开封高光** | 厂商密封盒（物理） | 录像中 SAR 等出现时的特效叠加、归属位高亮 | 在录像画面上叠加**任何遮挡卡面**的效果；剪辑改变时间顺序 |

**两条硬规则**：

1. **演出不得早于或独立于真实结果** —— 演出是结果的播放器，不是生成器
2. **演出可跳过，录像不可替代** —— 跳过演出直达结果与录像锚点；
   录像画面上的特效必须可关闭，保证审计视图是原始画面（I5）

## 5. MVP 切分

**MVP 唯一目标：实测 `m`（可接受溢价）与 `k`（合单系数）**（05 §10）。
不服务这两个数的功能，一律不进 MVP。

| 阶段 | 形态 | 包含 | 验证目标 |
|---|---|---|---|
| **MVP** | 自营 + 集中开盒 + 集中仓；**录像先行、直播不做** | M1（F1.1–1.3, F1.5）、M2（F2.1–2.5）、M3 全部、M4（F4.1–4.2）、M5（F5.1）、M6（F6.1–6.6）、M7（F7.1–7.4）、M9（F9.1–9.4）、M10（F10.2–10.6，自营用）、M11 全部 | `m`、`k`、满员率、分位验证点击率 |
| **P1** | 加直播、会员、第三方商家 | M4 演出、M5 直播、M8、F6.7、M10 入驻与结算 | 复购率、角色情感假设（F8.3/F8.4） |
| **P2** | 规模化 | 评级代送、社群、邀请 | — |

> **为什么 MVP 不做直播**：04 §6.4 已定直播 = 增益。MVP 期直播只增加成本、不产生 `m`/`k` 证据。
> 录像 + 延时发布足以完成信任闭环。
>
> **为什么 MVP 就做 F6.3 一键验证**：它是 H6"护城河只能是信任可见性"的直接落点，
> 也是区别于 DOPA 的**唯一用户可感知**的界面。不做它，MVP 测到的 `m` 就只是"又一家开盒站"的溢价。
